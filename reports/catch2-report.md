## 2. Platform-Specific Code Analysis

### 2.1 Architecture macros

| Macro | File | Semantics | Actual arch dispatch? |
|---|---|---|---|
| `__i386__`, `__x86_64__` | src/catch2/internal/catch_debugger.hpp | Select `int $3` debugger trap | Yes — debugger break only |
| `__aarch64__` | src/catch2/internal/catch_debugger.hpp | `.inst 0xd43e0000` / `0xd4200000` trap on Apple arm64 | Yes — debugger break only |
| `__arm__` + `__thumb__` | src/catch2/internal/catch_debugger.hpp | `.inst` trap on iOS ARM | Yes — debugger break only |
| `__POWERPC__` | src/catch2/internal/catch_debugger.hpp | PPC `sc` trap on macOS | Yes — debugger break only |
| `__SIZEOF_INT128__` | src/catch2/internal/catch_random_integer_helpers.hpp | Enables `__uint128_t` random multiply | Compiler capability; defined on riscv64 → works |
| `_MSC_VER` && `_M_X64` | src/catch2/internal/catch_random_integer_helpers.hpp | MSVC `_umul128` path | MSVC/x64-only → irrelevant to riscv |
| `_M_IX86_FP`, `__SSE2_MATH__` | tests/SelfTest/IntrospectiveTests/RandomNumberGeneration.tests.cpp | Disable float reproducibility tests on x86 without SSE2 | Test-only x86 guard; false on riscv |

No `__riscv*` macros exist anywhere in the repository. On riscv64/Linux the debugger trap falls through to the generic `raise(SIGTRAP)` fallback (`catch_debugger.hpp:58–61`), which is portable.

### 4.5 Bottleneck summary and causal analysis

1. Elapsed ratio 19.23x (baseline) is dominated by qemu-user dynamic binary translation, not riscv hardware: host instructions 22.4x, branches 23.7x, cycles 19.5x, 100 % of target samples in qemu/[JIT].
2. Higher target IPC (4.237 host vs 3.687) is a host artifact of qemu's high-ILP translation/dispatch loop.
3. Higher target branch-misprediction rate (0.263 % vs 0.168 %) and Bad Speculation (11.5 % vs 3.5 %) come from qemu's indirect-branch dispatch.
4. Lower target cache miss rates (L1d 0.177 % vs 0.278 %, LLC 13.30 % vs 18.01 %) are a working-set effect of the emulator's own hot structures, on ~20–33x more absolute accesses.
5. Top-down shape flip (Frontend 29.5 % vs 14.7 %; Backend 7.7 % vs 20.6 %) shows the host qemu process is instruction-fetch-bound, while the native benchmark is backend/memory-bound in FP statistics over `std::vector<double>`.
6. The native hotspots (bootstrap resampling, `SimplePcg32`, `standard_deviation`, `mean`) reflect Catch2's benchmark-statistics engine, and are scalar FP on both platforms.
7. After optimization, the optimizations cut guest work by ~30 % (instructions, cycles, branches, loads) on the target and gave 11.4 % native wall-clock improvement on x86; the target/reference elapsed ratio moved 19.23x → 15.10x, but this is measured under qemu and must not be read as native riscv hardware performance.

## 6. Notes About Exploration Process

- The provided `/work/input.yml` initially defined only x86 builds; the configurator confirmed a working riscv64 cross toolchain and qemu-user, and converted recipe 2 into a riscv64 static cross recipe, and later added optimized recipes 3 and 4. Both baseline and optimized target builds are riscv64 ELFs run under qemu-user on the x86_64 host, while both builds use platform ID 1 (the target architecture is carried by the recipe's cross toolchain, not a separate platform entry).
- QEMU/emulation caveat: all target timings and hardware counters are for the `qemu-riscv64` process on the x86_64 host and include emulation overhead; they do not reflect native riscv64 hardware performance. Target guest function hotspots are NOT AVAILABLE.
- `amixis build` wrote build trees relative to its own working directory (`/work/1_1_1`, `/work/1_1_2`, `/work/1_1_3`, `/work/1_1_4`) rather than inside `/work/catch2-workspace/`. Test logs are under `/work/catch2-workspace/logs/`.
- The baseline build recipe's intended `-O3` was neutralized by CMake appending `CMAKE_CXX_FLAGS_RELWITHDEBINFO` (`-O2`) after `CMAKE_CXX_FLAGS`, so baseline builds were effectively `-O2`; the optimized recipes override the per-config flags so `-O3` truly applies.
- `amphimixis-analyze-vectorization` succeeded for x86 but failed (exit 1) for riscv64; riscv vector counts are from an objdump fallback and are approximate.
- Reference L1-icache miss rate is NOT AVAILABLE (`cpu_core` "not counted").
- The target-vs-target cross-table (1_1_2 vs 1_1_4) is functionally uninformative because every symbol resolves to `[unknown]`.
- No profiling data was reconstructed or estimated; all reported numbers are directly measured or plain arithmetic from measured counters.
